1. PURPOSE

This baseline records the approved amendment of Bug Triage from a general-Jira Bug view to a dedicated, inventory-based operational queue.

BASELINE v0.11 remains a historical checkpoint and is not modified.

2. AUTHORITATIVE BUG TRIAGE SOURCES

Queue source:

- Jira Bug Triage export selected through the project latest-file convention: `Bug Triage_20260805.csv`

Assignees CSV is the only enrichment source, governing Team attribution for the Jira-export Assignee.

The general Jira PI backlog export does not govern Bug Triage membership.

3. APPROVED BUG TRIAGE SEMANTICS

Bug Triage is an inventory-based Jira operational queue.

- One row appears for every distinct valid Bug Triage export key.
- Tempo activity, worklogs, logged hours, Assignee presence, Team mapping, and the general Jira backlog export do not determine row inclusion.
- Unassigned Bugs and unmapped-assignee Bugs remain visible.
- Tempo does not participate in Bug Triage.
- Team is resolved only through the Assignees CSV using the Jira-export Assignee. Jira Team and Tempo Team are not used.
- Bug Severity remains Jira-owned, display-only metadata. It is never inferred, inherited, aggregated, grouped, used as a KPI, or made into a global filter.
- This deterministic reporting feature does not implement future AI Bug Intelligence capability.

4. TABLE IMPLEMENTATION

Details tab order remains:

1. Accounts
2. People
3. Backlog
4. Delivery Progress
5. Bug Triage

Bug Triage columns, in order:

1. Key
2. Summary
3. Bug Severity
4. Status
5. Updated
6. Assignee
7. Team

Default order is Bug Severity: Blocker, Critical, Major, Medium, Low, Enhancement, then `-`; Jira Key provides deterministic ordering within each severity. Existing sortable-column behavior remains available.

Updated is displayed exactly as stored in the dedicated Jira export. Team, Assignee, and Skill filter queue rows from current Jira-export Assignee mapping. Jira metadata filters apply only for metadata present in the dedicated export. No new global filter was added.
