3. BUG TRIAGE GOVERNANCE

Authoritative source:

Jira `Custom field (Bug Severity)`

Allowed values:

- Blocker
- Critical
- Major
- Medium
- Low
- Enhancement

Bug Severity is read-only, display-only metadata for operational Bug Triage. It is displayed exactly as stored in Jira. Missing values render as `-`; no fallback or parent inheritance is implemented.

Bug Severity does not participate in KPI calculations, reconciliation, grouping, aggregation, filtering, Team semantics, Backlog semantics, Delivery Progress semantics, Capacity, Logged Hours, or Original Estimate calculations.

4. APPROVED IMPLEMENTATION

Details tab order:

1. Accounts
2. People
3. Backlog
4. Delivery Progress
5. Bug Triage

Bug Triage contains only Jira work items where Work Item Type = Bug. Tempo operational rows do not appear.

Canonical columns, in order:

1. Key
2. Summary
3. Bug Severity
4. Priority
5. Status
6. Assignee
7. Team

Team continues to use the governed Assignees CSV mapping. Jira Team and Tempo Team are not used. The tab reuses the standard Details-table rendering, global filters, search, sorting, and placeholder behavior; it adds no filtering pipeline or global filter.
